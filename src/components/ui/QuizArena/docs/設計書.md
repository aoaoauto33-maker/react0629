## 3. 状態機械の設計（★重要：useReducer）

### 3-1. 状態遷移図

```text
                 START
idle ─────────────────────→ playing
                              │
                              │ SELECT / TIMEOUT
                              ▼
                         answered
                              │
                 ┌────────────┴────────────┐
                 │                         │
            NEXT(次問題)              NEXT(最終問題)
                 │                         │
                 ▼                         ▼
              playing                 finished
                                            │
                                            │ RESTART
                                            ▼
                                           idle
```

状態の意味：
- idle：クイズ開始前の状態
- playing：問題を表示し、回答受付中の状態
- answered：回答後、正誤判定と解説を表示している状態
- finished：全問題終了後、結果を表示している状態

---

### 3-2. State の形

```ts
type QuizState = {
  status: 'idle' | 'playing' | 'answered' | 'finished';
  questions: Question[];       // 出題する問題一覧
  currentIndex: number;        // 現在表示している問題番号
  score: number;               // 正解数
  selectedChoiceId?: string;   // 選択した選択肢
  isCorrect?: boolean;         // 正誤結果
  wrongQuestions: Question[];  // 間違えた問題一覧
  startTime: number;           // 開始時刻
  elapsedTime: number;         // 経過時間
};
```

---

### 3-3. Action の一覧

| Action | payload | 何が起きるか（状態の変化） |
|------|------|------|
| START | Question[] | 出題する問題を設定し、statusをplayingへ変更する |
| SELECT | choiceId | 選択肢を判定し、statusをansweredへ変更する。正解の場合scoreを+1する |
| TIMEOUT | なし | 制限時間切れとして不正解扱いにし、answeredへ変更する |
| NEXT | なし | 次の問題へ進む。最終問題の場合はfinishedへ変更する |
| RESTART | なし | 状態を初期状態（idle）へ戻す |

---

### 3-4. なぜ useState ではなく useReducer か（★必須）

クイズでは、回答・時間切れ・次へ進むなどのイベントによって、複数の状態（現在の問題番号、スコア、正誤結果、状態、間違えた問題一覧など）が同時に変化する。

useStateで個別に管理すると状態変更の処理が分散して複雑になるため、useReducerを使用して状態遷移のルールを1か所にまとめた。

これにより、「どのActionが発生したら、どの状態へ変化するか」を管理しやすくなる。

## 4. フックの採用理由

| フック | 使用箇所 | 目的・理由 |
|------|------|------|
| useReducer | QuizRunner | クイズ進行状態（開始・回答・終了など）と複数の値をまとめて管理するため |
| useEffect | Timer | setIntervalを使ったカウントダウン処理を実行し、終了時にクリーンアップするため |
| useRef | 未使用 | 今回の実装ではinterval ID保持や最新値参照が不要なため使用していない |
| useState | AppQ、StartScreen、Timer | 問題一覧、モード、カテゴリ、シャッフル設定、残り時間など単純な状態管理に使用する |
| useContext | 未使用 | 今回は親コンポーネントからPropsでデータを渡しているため使用していない |

---

### 4-1. Timer のクリーンアップ設計（T-3）

TimerではuseEffect内でsetIntervalを実行してカウントダウンを行う。

問題終了やコンポーネントの再描画時に古いintervalが残ると、複数のタイマーが同時に動作してしまうため、useEffectの戻り値でclearIntervalを実行して解除する。

依存配列にはsecondsとonTimeoutを指定し、制限時間が変更された場合やコールバックが変化した場合にタイマーを再設定する。

```ts
return () => {
  clearInterval(id);
};
```

## 5. ロジックの切り出し

判定・集計などの処理はコンポーネントから分離することで、テストしやすくする。

| 関数 | 役割 |
|------|------|
| buildOrder(questions, category, shuffle) | 選択されたカテゴリやシャッフル設定に応じて出題する問題配列を作成する |
| checkAnswer(question, choiceId) | 選択した選択肢が正解か判定する |
| calcResult(score, total, elapsedTime) | 正答数・正答率・所要時間を計算する |
| getWrongQuestions(questions, answers) | 間違えた問題だけを抽出して復習リストを作成する |
