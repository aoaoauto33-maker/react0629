# 1. 目的・背景

* **このアプリで何を実現するか（1〜2行）：**
フロントエンド技術（JavaScript / TypeScript / React）の知識を楽しく効率的にインプット・アウトプットできるクイズプラットフォームを提供する。

* **想定利用者：**
フロントエンド技術を学習中のエンジニア、新入社員、スキルチェックを行いたい開発者。

---

# 2. 機能一覧

| ID | 機能名 | 概要 | 備考 |
| :--- | :--- | :--- | :--- |
| F-1 | 作問フォーム | 独自のクイズ問題を作成し、バリデーションチェックを通過した問題を登録・一覧表示できる機能。 | React Hook Form + Yupによる入力検証 |
| F-2 | スタート画面 | カテゴリ選択（全件 / JavaScript / TypeScript / React）と出題順（登録順 / シャッフル）を設定してクイズを開始できる機能。 | 出題範囲を柔軟に変更可能 |
| F-3 | 制限時間タイマー | 問題ごとに設定された制限時間をカウントダウンし、0秒になった場合は自動的に不正解扱いとして回答済み状態へ遷移する機能。 | useEffect + setIntervalを使用 |
| F-4 | 回答・判定 | 選択肢をクリックすると即座に正誤判定を行い、結果と解説を表示する機能。 | 正解時はscoreを加算。不正解は復習リストへ追加 |
| F-5 | 次の問題へ | 解説確認後、次の問題へ進み、最終問題終了時には結果画面へ遷移する機能。 | useReducerで状態遷移を管理 |
| F-6 | 結果・復習 | クイズ終了後に正答数・正答率・所要時間を表示し、間違えた問題のみ復習リストとして表示する機能。 | 弱点確認と再挑戦を可能にする |
| F-7 | 状態管理 | アプリ内の状態を用途ごとに管理する機能。 | 作問データはuseState、クイズ進行状態はuseReducerで管理 |

# 4. データ定義

src/types.ts にクイズデータを管理する型を定義する。

## Category

問題のカテゴリを管理する型。

```ts
export type Category = 'JavaScript' | 'TypeScript' | 'React';
```

JavaScript、TypeScript、Reactの3種類のみを許可し、カテゴリ選択時の型安全性を確保する。

---

## Choice

1つの選択肢情報を管理する型。

```ts
export type Choice = {
  id: string;
  label: string;
};
```

idで選択肢を識別し、labelで画面に表示する選択肢内容を保持する。

---

## Question

1問分のクイズ情報を管理する型。

```ts
export type Question = {
  id: string;
  text: string;
  choices: Choice[];
  correctChoiceId: string;
  explanation: string;
  timeLimitSec: number;
  category: Category;
};
```

問題文、選択肢、正解、解説、制限時間、カテゴリなど、クイズ出題に必要な情報を保持する。

---

初期問題データの件数：8問

カテゴリ内訳：
- JavaScript（3問）
- TypeScript（2問）
- React（3問）

# 6. 判断ログ

| 論点（どこが曖昧だったか） | 決めたこと | 理由 |
| :--- | :--- | :--- |
| 制限時間が切れた場合の扱い | タイムアウトは不正解扱いとし、自動的にanswered状態へ遷移して復習リストへ追加する。 | 無回答の問題を明確に復習対象として管理することで、学習効率を高めるため。 |
| クイズ途中の離脱・リスタート時の挙動 | RESTART時はQuizRunnerの状態をinitialStateへ戻す。ただし作成済み問題データは保持する。 | 作成した問題を消さず、プレイ状態のみリセットすることで再挑戦しやすくするため。 |
| 問題データをどこで管理するか | 問題一覧はAppQのquestions stateで管理する。 | 作問モードとプレイモードの両方で同じ問題データを利用する必要があるため。 |
| useReducerを使用する範囲 | QuizRunner内のクイズ進行状態のみuseReducerで管理する。 | 回答・タイムアウト・次問題など複数状態が同時に変化するため、状態遷移を一元管理する必要があるため。 |
