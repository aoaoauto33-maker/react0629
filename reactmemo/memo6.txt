【フロントエンド】 Reactフック(基本)
7/21
フック理解のために
1. 通常のJavaScriptの前提として「関数は呼ばれるたびにリセットされる」
        ↓
2. Reactコンポーネントも実は「ただの関数」である
        ↓
3. 「でも、ボタンを押した回数を覚えておきたい」という困りごとがある
        ↓
4. その困りごとを解決するのが「フック」である
        ↓
5. フックは大きく「状態」と「副作用」の2つに分類される
        ↓
6. フックの2つのルール(呼び出し場所・順番)
        ↓
7. 個別のフック(useState, useEffectなど)の解説に入る

・フック(引っ掛ける)
値を覚えておく、useState
Stateがないと...
function increment() {
  let count = 0;
  count = count + 1;
  return count;
}

increment(); // 1
increment(); // また1(前回の結果は覚えていない)
increment(); // また1

・フックは主に２パターン
状態の管理(useState)
副作用(useEffect) => タイマーとか決まったタイミングで何かを実行

ルール1: フックは関数コンポーネントの「一番外側」でだけ呼び出す
ルール2: フックは「関数コンポーネント」か「カスタムフック」の中でしか呼び出せない

フックはとりあえずこれだけ覚えておけ
useState,useEffect,useRef


・useEffect...決まったタイミングで何か処理を実行したい時に使うフック
Reactの外側と連携(ネットワークからデータ取得、ブラウザアクセスなど)するときに使ったりする
useEffect(() => {
  // ここに実行したい処理を書く

  return () => {
    // ここに「後片付け」の処理を書く(省略可能)
  };
}, [依存配列]);
第一引数に処理、第二引数に依存配列[]、[count]、なにも書かないなど

countが変わるたびに実行 => [count]
最初の1回だけやりたい処理 => []
再レンダリングのたびに実行 => なにも書かない

setInterval => 第一引数に処理、第二引数に秒数で第二引数後にタイマー開始、一定時間ごとに同じ処理を繰り返す
clearInterval => 引数として渡したものが消えた時にタイマー終了、これがないと描画を
終わらせてもメモリがクリアされず、自分のPCがどんどん重くなってしまう




・useLayoutEffect(ランクA)
useEffectは画面描画後に非同期で実行
useLayoutEffectは画面描画前に同期で実行される
useLayoutEffect(() => {
        sleep(2000);
        setCount(init);
    }, []);
    2秒間遅らせる処理をして、setCountに初期値を入れる
    依存配列が[]なので最初の一度だけ実行

useEffect =>　古いのが表示されてから新しいのを表示
useLayoutEffect =>最初から最新の情報を表示

・useRef...値を保存しておく、useStateと同じような役割
直接HTMLに接続する(getElementByIdみたいな)、要素オブジェクトへのアクセスが目的
あんまり使っては行けない、必要でない場合はuseStateを使うべし
useRef関数は要素へのフォーカス/スクロール/アニメーション操作のような限られた状況

useRefは、useState同様に値を保持するフックだが、決定的に異なる性質を1つ持つ
=>useRefは保持した値が変わってもコンポーネントは再描画されない(役に立つのそれ？) テスト出る

なぜuseRefは濫用しちゃいけないの？
=> Reactの根本的な設計思想に反する使い方になりがちだから
Reactはそもそも変化した部分だけ再描画するのがメインの機能だから、それに反する
いちいち再描画の命令を出さなきゃいけない

パターン1: DOM要素そのものに直接アクセスしたいとき
inputRef.current? = <input> HTMLの要素を持たせる
(使い道)動画の再生・停止を制御できる

パターン2: 「再描画を起こしたくない値」を保持したいとき
useState = 再描画される
useRef = 再描画されない
useRefを押したときは内部は変わっても再描画されないが、useStateを押した瞬間Stateの
再描画に引っ張られて再描画してくれる
=> つまりuseRefは、「再描画をまたいで値を覚えておきたいが、その値が変わったからといって
画面を更新する必要はない」というときに使う箱

const file = useRef(初期値);
file = { current: 初期値 }currentはキーのようなもの

StrictModeとは...一度作った料理をもう一回作ってちゃんとできるかな？という確認 邪魔だったらoff


useRefを利用しない例
再描画のたびにid = null になってしまい開始した時のidが消えてしまう、止められない

useRefを利用する例
idの値が保持されるから止めることができる

・Refをコンポーネント配下の要素にフォワードする
refを使う処理でも、コンポーネントを分けて使えますよーーー

・リモコン、むずいやつ(復習必須)
useImperativeHandle = 子コンポーネントが、親に公開する機能(メソッド)
を決めるためのフック、複数機能もつけられる
(説明)
親は子の中身を直接触るのではなく、子が「これだけ使っていいよ」と公開
したメソッドだけをref経由で呼び出せるようにする仕組み。これによって
子の実装を隠しつつ、必要な操作だけ親に提供できる。
useImperativeHandle(ref, () => ({
    focus() {
        inputRef.current?.focus();
    }
}));
第一引数に親からもらった命令を受け取っている
自分で作ったfocus()というボタンの中身をuseImperativeHandleで書いている

・useReducer関数　状態と処理とをまとめて管理する
useStateとよく似たフックだが、useReducerは状態の操作も管理する
useStateは更新処理がコンポーネントの随所に散乱しがち
Reducerは普通の関数だが、直接呼び出すことはできない
[state, dispatch]
dispatchに送った命令に従ってReducerの中身を実行する

Reducerにしかできないこと => ない、使わなくてもなんとかなる
複雑になってきた時にコードを綺麗にできる


・use関数　コンポーネントの複数階層で値を受し渡する
Reactの世界ではPropsが親コンポーネントから子コンポーネントの情報伝達を担うのが基本
今までの知識では親 => 子、子　=> 孫とそれぞれでpropsを渡していた
親から子、孫へとPropsの受け渡しは冗長であり、何らかしらの誤りの原因になる
=> そんな時にuse関数を使うべし
Context(文脈、背景)を使うと親 => 孫と子コンポーネント経由なしでContextが渡せる

const context = use(MyAppContext); Contextから値を取り出すフック
親がContextに登録したデータを孫が取り出す(３階層程度だと微妙だが階層が深まれば便利)
属性名はvalueになる

nullとundefined 役割は一緒
null => 値がなくてもいいよ、ないよ
undefined => 値がないとだめ、でもない Contextは何か入ってないとダメ？

<フックまとめ>
・useState
❌ 値を保存したいから
⭕ 画面に表示する値なので、変更されたら再レンダリングしてほしいから
使用例
・カウンター
・入力フォーム
・モーダルの表示・非表示

--------------------------------------------------
・useRef
❌ タイマーだから
⭕ 再レンダリングしてほしくないが、値は保持したいから
使用例
・タイマーID
・inputのfocus
・DOM取得

--------------------------------------------------
・useEffect
❌ APIだから
⭕ レンダリング後に実行すれば十分な処理だから、非同期じゃないけど非同期っぽい
使用例
・API取得
・イベント登録
・タイマー開始・停止
・localStorageへの保存

--------------------------------------------------
・useLayoutEffect
❌ DOMを取得したいから
⭕ 画面表示前にDOMを取得・調整しないと、チラつきやレイアウト崩れが起こるから
使用例
・要素の幅・高さ取得
・スクロール位置調整
・アニメーション開始位置の調整

--------------------------------------------------
・useReducer
❌ カートだから
⭕ 状態変更が多いので、更新処理を1か所にまとめたいから
使用例
・ショッピングカート
・Todo
・複雑なフォーム

--------------------------------------------------
・Context
❌ 親から孫へ渡したいから
⭕ Props Drilling(propsの受け渡しリレー)を防ぎ、必要なコンポーネントが直接データ
を取得できるようにするため
使用例
・ログインユーザー情報
・テーマ（ダークモード）
・言語設定
