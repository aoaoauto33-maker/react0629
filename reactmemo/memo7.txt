メモ化
・関数またはその結果をメモ化する(memo/useMemo/useCallback)
メモ化...関数の呼び出し結果をキャッシュしておき、後で再利用すること
あんま使わない方がいいかも、何をキャッシュすればいいのか考える必要がある


＊オーバーヘッド:本来の目的を達成するために、付随的に必要となってしまう余計な手間やコスト

・計算結果だけをメモ化(useMemo)
    const heavyProcess = useMemo(() => {
        sleep(1000);
        return count1 + 100;
    }, [count1] );
依存配列に入れた値が変わった時だけもう一度計算して
それまでは計算結果を記憶しておいて再利用
useMemoはコンポーネントの実行を止める機能ではない

count2を押した時にuseMemoで記憶したcount1の計算結果をそのまま出す(処理が軽くなる)
count2を押してもuseMemoに記憶してるのはcount1だけなので中身の処理は実行されず
貼り付けるだけ

・コンポーネントの再描画を抑制する(memo)
memo関数は前回と今回のpropsを比較してくれる
受け取ったpropsを判定する関数なので基本的に子コンポーネントで使うもの
親が再レンダリングされても、propsが変わらなければ子は再レンダリングされない
jsの性質として、関数は実行されるたびに新しい関数を作るのでbtnも実行される

・関数定義そのものをキャッシュする(useCallback)
再レンダリングせずに関数を使い回したい時に使う
useCallbackが一番効果を発揮するのは「子コンポーネントに渡す関数props」に対して
=> 関数の参照を固定したい場面で使う

・再レンダリングと画面更新は別物(重要)
再レンダリング...コンポーネント関数がもう一度実行されること
状態変更
 ↓
コンポーネント再実行（再レンダリング）
 ↓
新しい仮想DOMを作る
 ↓
前の仮想DOMと比較（Diff）
 ↓
変更部分だけ本物のDOM更新

用語           意味
----------------------------------------
再レンダリング   コンポーネント関数が再実行されること
仮想DOM更新     新しいJSX（仮想DOM）を作ること
DOM更新        ブラウザ画面を書き換えること

useCallbackを使うとbtn1のコンポーネント自体の再レンダリングを防ぐのではなく、
btn1に渡している関数propsが変わらなくなるので、memoを使った子コンポーネントの
再レンダリングを防げる

・優先順位の低いState更新を区別する(useTransition)
値が変わったら画面を再描画する機能はJSにはなく、Reactがやっている
ReactはStateとページとを同期するライブラリ

複数のStateに応じてページを制御する
find()は条件に合う最初の要素を一つ返すメソッド. 配列.find(条件)

*今は実際のデータをて入力しているが本番はデータベースに入れる

・useTransition...軽い処理を先にやって重い処理を後から行う
startTransition(() => {
    setComments(...);
});
Reactが「このState更新は急がなくていいんだな」と判断して更新の優先順位を下げているだけ
isPendingはreactが勝手にfalseにしてくれるので初期値を書く必要はない
startTransition(後回し処理)が始まったらisPendingをtrueに、終わったらfalseに

・useDeferredValue
useTransitionによく似た機能のuseDeferrdValue関数
useDeferValue(text)でtextの遅延した値をコピーしている、遅延した値が欲しい時に使う
useTransitionは優先順位をつけているだけ、状態の更新を遅くしたい
